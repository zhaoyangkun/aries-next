# Aries Next 文档中心

本目录是项目的权威文档。所有文档遵循统一的写作与维护规范，修改文档前请先阅读本文。

## 文档地图

| 文档 | 类型 | 内容 |
|---|---|---|
| `architecture.md` | 概念 | 系统架构、模块边界、权限模型 |
| `implementation-plan.md` | 概念 | 实施规划与里程碑（历史决策记录，随 Phase 推进滚动更新状态） |
| `phases/` | 概念 | 各 Phase 的目标、范围与验收标准 |
| `database-mapping.md` | 参考 | 旧版 MySQL 到 PostgreSQL 的数据映射 |
| `migration-runbook.md` | 操作 | Production Cutover 与 Rollback 操作手册 |
| `production-deployment.md` | 操作 | 生产部署手册（Bare-metal：Systemd、Nginx、HTTPS、备份与回滚） |
| `docker-deployment.md` | 操作 | 部署唯一权威文档（Docker Compose、环境变量与安全项、自动化脚本、备份与回滚；原 `deployment.md` 已并入） |
| `openapi.yaml` | 参考 | API 契约（唯一权威来源，禁止手写副本） |
| `adr/` | 概念 | 架构决策记录（Architecture Decision Record） |

文档类型借鉴 Diátaxis 框架：**概念**（解释为什么）、**操作**（怎么做一件事）、**参考**（精确查阅）。写新文档前先想清楚它属于哪一类。

## 写作规范

1. **语言**：以简体中文为主；专有名词、技术名词、代码标识符保留 English（如 Repository、Migration、SSE、PostgreSQL），不强行翻译。
2. **排版**：中文与英文、中文与数字之间加一个空格（如「使用 PostgreSQL 17 存储」）；标点用中文全角；代码、命令、路径、环境变量、URL 一律用反引号包裹。
3. **结构**：每篇文档开头用一小节说明「本文档回答什么问题、写给谁看」；正文用二级标题分节；长文档在开头给目录。
4. **准确**：事实性内容（命令、配置项、端点、表结构）必须与代码一致。易变的细节（如完整端点清单、完整环境变量列表）引用代码路径或 `openapi.yaml`，不在 Markdown 里复制副本——文档应解释「是什么、为什么、去哪里查」，而不是重复代码。
5. **时效**：涉及时效性内容的文档在开头标注「最后验证日期」；Phase 文档用状态标记：✅ 已完成、🚧 进行中、⬜ 未开始。
6. **安全**：文档不得包含真实密码、Token、生产连接串；示例一律用占位符。
7. **简洁**：能一句话说清的不用三句；删除过时内容而不是叠加补丁；避免「众所周知」「众所周知地」「简单来说」等填充词。

## 维护规则

- 架构变化必须新增 ADR（见 `adr/0001` 的格式），而不是直接改写旧结论。
- API 契约变化只改 `openapi.yaml`；其他文档引用它，不复制端点细节。
- 功能完成后更新对应 Phase 文档的状态标记，并在文末记录与原计划的关键偏差。
